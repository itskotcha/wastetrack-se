## 2. ระบบของเรา

- ระบบนี้ทำอะไร (2–3 ประโยค): ระบบ **WasteTrack** เป็นแอปพลิเคชันบนโทรศัพท์เคลื่อนที่ระบบปฏิบัติการ Android (Mobile App) แบบรวมศูนย์เพียงช่องทางเดียว สำหรับติดตามตำแหน่งรถเก็บขยะด้วย GPS แบบเรียลไทม์ แสดงสถานะจุดจัดเก็บบนแผนที่โดยยืนยันผ่าน Geofencing และ Haversine Formula ร่วมกับการยืนยันของพนักงาน แนะนำเส้นทางเดินรถด้วยแนวคิด VRP และ Clarke-Wright Savings Algorithm รวมถึงรองรับแดชบอร์ดเชิงพื้นที่ การจัดการจุดถังขยะ การแจ้งปัญหาขยะ และการมอบหมายงานแก้ไขภายในแอปพลิเคชันเดียวกัน
- ผู้ใช้หลักและผู้มีส่วนได้ส่วนเสีย (ใครใช้ ใครได้รับผลกระทบ):
  - **ประชาชนในพื้นที่ (15 หมู่บ้าน):** ผู้ใช้งานหลัก (ไม่ต้องเข้าสู่ระบบ) ใช้ดูตำแหน่งรถเก็บขยะและสถานะจุดจัดเก็บ รวมถึงแจ้งปัญหาขยะพร้อมรูปภาพและพิกัด
  - **พนักงานเก็บขยะ:** ผู้ปฏิบัติงานหลัก ใช้ดูเส้นทางที่แนะนำ ยืนยันผลการจัดเก็บ ณ จุดปฏิบัติงาน และรับ/รายงานผลแก้ไขงานที่ได้รับมอบหมาย
  - **เจ้าหน้าที่หน้าเคาน์เตอร์:** ผู้ใช้งานระบบ ใช้บันทึกการแจ้งปัญหาขยะแทนประชาชนที่ไม่สะดวกหรือไม่มีทักษะการใช้แอปพลิเคชัน (เช่น ผู้สูงอายุ)
  - **หัวหน้าฝ่าย:** ผู้บริหารจัดการระบบ ใช้ติดตามรถ ดูแดชบอร์ดสรุปข้อมูลเชิงพื้นที่รายหมู่บ้าน มอบหมายงานแก้ไขปัญหา และจัดการเพิ่ม/ลบจุดถังขยะ
- ผู้ใช้จริงที่จะชวนมาทำ UAT ได้ (หน่วยงานหรือกลุ่มผู้ใช้ ไม่ต้องใส่ชื่อบุคคล): บุคลากรและประชาชนในเขตพื้นที่รับผิดชอบของ **องค์การบริหารส่วนตำบลแม่คะ อำเภอฝาง จังหวัดเชียงใหม่** (ประกอบด้วย หัวหน้าฝ่าย พนักงานเก็บขยะ เจ้าหน้าที่หน้าเคาน์เตอร์ และประชาชนตัวแทนจากพื้นที่ 15 หมู่บ้าน รวมถึงผู้สูงอายุหรือผู้ที่ไม่ถนัดใช้เทคโนโลยี)
- การ deploy (ทดสอบที่ไหน ใช้งานจริงที่ไหน):
  - **สภาพแวดล้อมการทดสอบและใช้งานจริง:** Backend/API Server และ Database (PostgreSQL) โฮสต์บนคลาวด์ผ่านบริการ **Supabase (Free Tier)** ส่วนแอปพลิเคชันฝั่งผู้ใช้ติดตั้งผ่านไฟล์ติดตั้ง **APK บนสมาร์ตโฟน Android (เวอร์ชัน 8.0 / API 26 ขึ้นไป)** ของผู้พัฒนาและผู้เข้าร่วมทดลองใช้งานในพื้นที่จริงของ อบต.แม่คะ

## 4. สถานะตอนนี้

- Sprint ปัจจุบันและสิ่งที่กำลังทำ: อยู่ในช่วง **Sprint 2 (สัปดาห์ที่ 3–4 ของแผนโครงงาน)** กำลังดำเนินการรวบรวมและตรวจสอบความครบถ้วนของข้อมูลพิกัดจุดถังขยะจากการลงพื้นที่ ออกแบบโมเดลระบบและฐานข้อมูล ตั้งค่าโครงสร้างโปรเจกต์ Supabase (RBAC/RLS) และพัฒนาโครงร่างการเข้าสู่ระบบ 3 บทบาทพร้อมการเชื่อมต่อแผนที่เริ่มต้น
- ส่วนที่ทำเสร็จแล้ว:
  - วิเคราะห์ปัญหาและกระบวนการทำงาน (AS-IS / TO-BE) และวิเคราะห์ผู้มีส่วนได้ส่วนเสียครบ 4 บทบาท
  - กำหนดความต้องการเชิงธุรกิจ (BR-01–BR-09), เชิงหน้าที่ (FR-01–FR-11), นอกเหนือหน้าที่ (NFR-01–NFR-10), Use Case (UC-01–UC-13) และตารางสอบกลับ (RTM)
  - ออกแบบสถาปัตยกรรมเบื้องต้น (C4 ระดับ C1 และ C2) และแผนการทดสอบระดับระบบ (TC-01–TC-09)
  - ลงพื้นที่เก็บข้อมูลพิกัดจุดถังขยะเบื้องต้น (ช่วงวันที่ 9–14 พฤศจิกายน 2569)
- การทดสอบที่มีอยู่แล้ว (ถ้ายังไม่มี เขียนว่ายังไม่มี): **ยังไม่มี** (กำหนดแผนกรณีทดสอบ TC-01 ถึง TC-09 ไว้แล้วในสถานะ “วางแผนแล้ว” และจะเริ่มรัน Unit/Integration Test ควบคู่กับการพัฒนาโมดูลในรอบถัดไป)

## 5. ส่วนที่ทีมคิดว่าเสี่ยงที่สุด 3 อย่าง

ใช้ในการวางแผนการทดสอบตามความเสี่ยงครั้งที่ 5 (CP2)

| ส่วนของระบบ | ทำไมคิดว่าเสี่ยง | ถ้าพังจะกระทบใคร อย่างไร |
|---|---|---|
| **1. การติดตามตำแหน่ง GPS และการตรวจจับรัศมี Geofencing + Haversine Formula** | สัญญาณ GPS ในพื้นที่จริงอาจมีความคลาดเคลื่อน หรือเกิดปัญหาการส่งพิกัดขณะแอปทำงานอยู่เบื้องหลัง (Background Location) รวมถึงการคำนวณระยะห่างที่อาจแจ้งเตือนซ้ำหรือคลาดเคลื่อนจากรัศมีที่กำหนด | **พนักงานเก็บขยะ ประชาชน และหัวหน้าฝ่าย:** ตำแหน่งรถบนแผนที่ไม่อัปเดตหรือคลาดเคลื่อน ทำให้ประชาชนกะเวลานำขยะออกมารอผิดพลาด พนักงานไม่ได้รับหน้าต่างยืนยันผลการจัดเก็บ ณ จุดจริง และสถานะจุดจัดเก็บไม่เป็นปัจจุบัน |
| **2. การควบคุมสิทธิ์การเข้าถึงข้อมูลตามบทบาท (RBAC & Row Level Security บน Supabase)** | ระบบรวมฟังก์ชันและแดชบอร์ดของผู้ใช้ทั้ง 4 บทบาทไว้ในแอปพลิเคชันเดียว (โดยประชาชนไม่ต้องเข้าสู่ระบบ) หากตั้งค่านโยบาย RLS หรือสิทธิ์ API ผิดพลาด อาจเกิดช่องโหว่การเข้าถึงข้อมูลข้ามบทบาท | **หัวหน้าฝ่าย พนักงาน และประชาชนผู้แจ้งปัญหา:** ผู้ที่ไม่มีสิทธิ์อาจเข้าไปเพิ่ม/ลบจุดถังขยะ มอบหมายงาน หรือเข้าถึงข้อมูลพิกัด/รูปภาพการแจ้งปัญหาและตำแหน่งปฏิบัติงานของพนักงานโดยไม่ได้รับอนุญาต ทำให้ข้อมูลตั้งต้นของระบบเสียหายและกระทบความเป็นส่วนตัว |
| **3. การคำนวณแนะนำเส้นทาง (VRP + Clarke-Wright Savings) และการซิงค์ข้อมูลจุดถังขยะ** | การคำนวณเส้นทางใช้ระยะเส้นตรงจากพิกัด (Haversine) ไม่ใช่โครงข่ายถนนจริง และต้องพึ่งพาข้อมูลจุดถังขยะที่หัวหน้าฝ่ายเพิ่ม/ลบแบบไดนามิก รวมถึงความเสี่ยงที่โปรเจกต์ Supabase Free Tier จะพักการทำงานหากไม่มีการใช้งานต่อเนื่อง 7 วัน | **พนักงานเก็บขยะและหัวหน้าฝ่าย:** ระบบอาจแนะนำลำดับจุดจัดเก็บที่ไม่สอดคล้องกับเส้นทางจริง หรือยังนำจุดที่ถูกลบไปแล้วมาคำนวณ ส่งผลให้รถเก็บขยะเดินทางซ้ำ สิ้นเปลืองเวลาและเชื้อเพลิง หรือระบบไม่สามารถเชื่อมต่อฐานข้อมูลได้ขณะปฏิบัติงานจริง |
