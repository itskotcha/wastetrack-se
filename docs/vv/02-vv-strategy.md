## 1. ระดับความสำคัญของระบบ (integrity level ตาม IEEE 1012)

ใช้ตารางท้ายไฟล์ เลือกระดับของทั้งระบบ แล้วระบุส่วนที่ควรสูงกว่าระดับของทั้งระบบ (ถ้ามี)

| คำถาม | คำตอบของทีม |
|---|---|
| ถ้าระบบทำงานผิด ผลเสียร้ายแรงที่สุดคืออะไร เกิดกับใคร | ภารกิจการจัดเก็บขยะประจำวันและการติดตามงานล่าช้า หรือข้อมูลเส้นทาง/สถานะจุดจัดเก็บผิดพลาด (เกิดกับพนักงานเก็บขยะ ประชาชน 15 หมู่บ้าน และหัวหน้าฝ่าย) รวมถึงความเสี่ยงข้อมูลพิกัดและรูปภาพส่วนบุคคลรั่วไหลหากกำหนดสิทธิ์ผิดพลาด |
| ความรุนแรงของผลเสีย (ร้ายแรงมาก / ร้ายแรง / ปานกลาง / เล็กน้อย) | ปานกลาง (งานล่าช้า ข้อมูลผิดบางส่วน ต้องแก้ด้วยมือ) |
| โอกาสเกิด (เกิดได้แน่ / น่าจะเกิด / บางครั้ง / แทบไม่เกิด) | น่าจะเกิด (โดยเฉพาะความคลาดเคลื่อนของสัญญาณ GPS และข้อมูลจุดถังขยะที่เปลี่ยนแปลงในพื้นที่จริง) |
| integrity level ของทั้งระบบ (1–4) และเหตุผล 1–2 ประโยค | **ระดับ 2** — ระบบเป็นแอปพลิเคชันต้นแบบสนับสนุนการติดตามรถและบริหารจัดการขยะ ไม่มีผลกระทบต่อชีวิตหรือการสูญเสียทรัพย์สินโดยตรง หากข้อมูลคลาดเคลื่อนพนักงานยังสามารถปฏิบัติงานและยืนยันผลหน้างานด้วยตนเองได้ |
| ส่วนที่ระดับสูงกว่า และเหตุผล | **ระดับ 3 สำหรับโมดูลควบคุมสิทธิ์ (RBAC / Row Level Security บน Supabase) และระบบเช็คพอยต์ Geofencing + Haversine** — เนื่องจากต้องป้องกันการเข้าถึงข้อมูลพิกัด/รูปภาพส่วนบุคคลข้ามบทบาทหรือการลบจุดถังขยะโดยผู้ไม่มีสิทธิ์ (ความรุนแรงระดับร้ายแรงด้านข้อมูลรั่วไหล) และต้องตรวจจับตำแหน่งให้แม่นยำตามเกณฑ์ NFR-09 (≥ 90%) |

## 2. ทดสอบอะไร ระดับไหน เมื่อไร

ต่อจากตารางในคาบ แต่ละระดับระบุส่วนของระบบของทีมเอง Sprint ที่ทำ เครื่องมือ และผู้รับผิดชอบ

| ระดับการทดสอบ | ทดสอบอะไรในระบบของเรา | Sprint หรือช่วงเวลา | เครื่องมือ | ผู้รับผิดชอบ |
|---|---|---|---|---|
| component (unit) | ฟังก์ชันคำนวณระยะทาง Haversine Formula, การตรวจสอบรัศมี Geofence (ไม่แจ้งซ้ำในรอบเดิม), อัลกอริทึมจัดเส้นทาง Clarke-Wright Savings และการตรวจสอบสิทธิ์เพิ่ม/ลบจุดถังขยะ | Sprint 3–5 (สัปดาห์ที่ 5–10) ควบคู่การพัฒนาแต่ละรอบ | Flutter Test (`flutter_test`), Deno Test (สำหรับ Supabase Edge Functions) | กชพร (Backend/Engine), ดาวประกาย (Mobile UI/Logic) |
| integration | การเชื่อมต่อระหว่าง Mobile App (Flutter) ↔ Supabase (Auth, PostgREST, Edge Functions, Storage, Realtime) ↔ Database (PostgreSQL) และการเรียกใช้ Tracking & Route Engine | Sprint 6 (สัปดาห์ที่ 11–12) | Postman / REST Client, Supabase Local/Dashboard, Flutter Integration Test | กชพร และ ดาวประกาย |
| system | การทำงานครบทุกฟังก์ชัน FR-01 ถึง FR-11 และ UC-01 ถึง UC-13 ตามกรณีทดสอบ TC-01 ถึง TC-09 รวมถึงการทดสอบเชิงลบของ RBAC/RLS และเกณฑ์ NFR-01 ถึง NFR-10 | Sprint 7 (สัปดาห์ที่ 13–14) | Android Physical Devices (API 26+), Mock GPS / ชุดพิกัดทดสอบจริง 15 หมู่บ้าน | กชพร และ ดาวประกาย |
| acceptance (UAT) | การทดลองใช้งานจริงตามบทบาททั้ง 4 กลุ่ม (หัวหน้าฝ่าย พนักงานเก็บขยะ เจ้าหน้าที่หน้าเคาน์เตอร์ และประชาชนในพื้นที่ อบต.แม่คะ) พร้อมประเมินความพึงพอใจ (≥ 3.50/5.00) และความเหมาะสมต่อหน้างาน | Sprint 7 (สัปดาห์ที่ 13–14) | ไฟล์ติดตั้ง APK บน Android จริง, แบบสอบถาม 5 ระดับ, แบบบันทึกข้อเสนอแนะ (Defect Log) | ดาวประกาย (ผู้นำ UAT) และ กชพร |

## 4. ชนิดการทดสอบ

- **เชิงฟังก์ชัน:** ทดสอบความต้องการเชิงหน้าที่ครบทั้ง **11 ข้อ (FR-01 ถึง FR-11)** ครอบคลุม 13 Use Cases (UC-01 ถึง UC-13) ตามกรณีทดสอบหลัก **TC-01 ถึง TC-09** ได้แก่ การเข้าสู่ระบบ 3 บทบาท (FR-01), การติดตามพิกัด GPS แบบเรียลไทม์ (FR-02), การตรวจจับ Geofencing + Haversine (FR-03), การยืนยันผลการจัดเก็บรายจุด (FR-04), การแสดงสถานะจุดบนแผนที่ (FR-05), การแนะนำเส้นทาง Clarke-Wright (FR-06), แดชบอร์ดเชิงพื้นที่ (FR-07), การแจ้งปัญหาขยะด้วยตนเองและผ่านเคาน์เตอร์ (FR-08, FR-09), การจัดการจุดถังขยะพร้อมบันทึกประวัติ (FR-10) และการมอบหมายงาน/รายงานผลการแก้ไข (FR-11)
- **เชิงไม่เป็นฟังก์ชัน:** 2 คุณลักษณะที่สำคัญที่สุดตาม ISO/IEC 25010 และเหตุผล
  1. **Security (NFR-01, NFR-02 — การควบคุมสิทธิ์ตามบทบาท RBAC):** ระบบรวมหน้าจอและแดชบอร์ดของทั้ง 4 บทบาทไว้ในแอปเดียวและเปิดให้ประชาชนเข้าใช้งานได้โดยไม่ต้องล็อกอิน จึงต้องมั่นใจว่าผู้ใช้ไม่สามารถเข้าถึงข้อมูลส่วนบุคคล (พิกัด/รูปภาพ) หรือแก้ไขข้อมูลตั้งต้น (จุดถังขยะ/การมอบหมายงาน) ข้ามสิทธิ์ได้
  2. **Functional Suitability – Functional Correctness & Performance Efficiency (NFR-07, NFR-09 — ความถูกต้องเชิงตำแหน่งและความทันเวลา):** หัวใจหลักของระบบคือการแสดงตำแหน่งรถและสถานะจุดบนแผนที่ให้เป็นปัจจุบันภายในไม่เกิน 10 วินาที และจำแนกพิกัดเข้า-ออกรัศมี Geofence ได้ถูกต้องไม่น้อยกว่าร้อยละ 90 ท่ามกลางความคลาดเคลื่อนของ GPS ในพื้นที่จริง
- **regression:** ทดสอบซ้ำชุดกรณีทดสอบหลัก (**TC-01 ถึง TC-09**) โดยเฉพาะการตรวจจับ Geofencing (TC-02), การคำนวณเส้นทางหลังจากเพิ่ม/ลบจุดถังขยะ (TC-03, TC-08) และการควบคุมสิทธิ์ RBAC (TC-05) ทุกครั้งที่มีการแก้ไขโค้ดหลังพบข้อบกพร่องหรือก่อนรวมโค้ดเข้าสู่สาขาหลัก (Main Branch) ในช่วง Sprint 5–8
- **สิ่งที่ตั้งใจไม่ทดสอบ และเหตุผล:**
  - **การหาเส้นทางที่ดีที่สุดตามโครงข่ายถนนจริงและสภาพการจราจร (Turn-by-turn Navigation / Real-time Traffic):** ขอบเขตโครงงานกำหนดให้คำนวณเส้นทางแบบฮิวริสติก (Clarke-Wright Savings) จากระยะเส้นตรง Haversine สำหรับรถ 1 คันต่อวันเท่านั้น
  - **Load / Stress Testing ปริมาณผู้ใช้จำนวนมากระดับหมื่นรายพร้อมกัน:** ระบบเป็นต้นแบบระดับตำบล (15 หมู่บ้าน) ที่ใช้งานภายในหน่วยงานและประชาชนในพื้นที่ของ อบต.แม่คะ จึงทดสอบเฉพาะการใช้งานจริงตามสภาพแวดล้อมต้นแบบและเกณฑ์เวลาตอบสนอง NFR-07 (≤ 10 วินาที)

## 5. ส่วนที่เสี่ยงจาก V&V Profile

| ส่วนที่เสี่ยง (จาก V&V Profile ข้อ 5) | ระดับหรือวิธีที่จะจับข้อบกพร่องได้เร็วที่สุด |
|---|---|
| **1. การติดตามตำแหน่ง GPS และการตรวจจับรัศมี Geofencing + Haversine Formula** | **Unit Testing + Simulation (ตั้งแต่ Sprint 3):** เขียน Unit Test จำลองชุดพิกัดทั้งในรัศมี นอกรัศมี และพิกัดที่แกว่งคลาดเคลื่อน เพื่อยืนยันความแม่นยำ (≥ 90%) และเงื่อนไขไม่แจ้งเตือนซ้ำ ก่อนนำไปทดสอบวิ่งจริงบนอุปกรณ์ Android ในพื้นที่ |
| **2. การควบคุมสิทธิ์การเข้าถึงข้อมูลตามบทบาท (RBAC & Row Level Security บน Supabase)** | **Static Design/Policy Review + Negative API/Integration Testing (ตั้งแต่ Sprint 2–3):** ทบทวน SQL/RLS Policy ร่วมกัน 2 คนก่อนใช้งาน และยิงทดสอบ API เชิงลบ (Negative Test) ด้วย Token ของแต่ละบทบาท (และผู้ใช้ที่ไม่ล็อกอิน) เพื่อจับช่องโหว่การเข้าถึงข้ามสิทธิ์ทันทีที่สร้างตาราง |
| **3. การคำนวณแนะนำเส้นทาง (VRP + Clarke-Wright Savings) และการซิงค์ข้อมูลจุดถังขยะ** | **Unit Testing กรณีขอบเขต (Edge Cases) + Automated Health Check (Sprint 4–5):** ทดสอบฟังก์ชันคำนวณเส้นทางทันทีหลังเพิ่ม/ลบจุดถังขยะเพื่อยืนยันว่าจุดที่ลบไม่ถูกนำมาคำนวณซ้ำ และตั้งงานอัตโนมัติ (Cron/Ping) ป้องกัน Supabase Free Tier พักการทำงานก่อนทดสอบจริง |
